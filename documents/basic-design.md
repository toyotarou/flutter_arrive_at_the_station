## 1. プロジェクト概要

### 1.1 背景

電車通勤・通学・旅行中に居眠りで目的の駅を乗り越してしまう問題に対し、前作「降りタイマー (oriTimer)」では東京の路線に限定していた。本アプリは日本全国の路線・駅に対応し、さらに地図からの直感的な駅選択と現在地ベースの近傍駅表示を加えた後継アプリである。

### 1.2 目的

- 日本全国の任意の駅の半径1000m圏内に入ったとき、プッシュ通知・ループバイブレーションでユーザーに通知する
- 都道府県マップタップによる直感的な駅選択を実現する
- 現在地周辺の近傍駅を地図上に表示し、すばやく目的地を設定できるようにする

### 1.3 対象ユーザー

- 開発者自身（個人利用）
- 地方出張・旅行・帰省などで電車を使う人（将来的な共有を想定）

### 1.4 スコープ（対象範囲）

**対象範囲（作るもの）:**

- 日本全国都道府県ポリゴンの地図表示
- 都道府県別の路線・駅一覧表示（APIから取得）
- 近傍駅の地図表示（GPS位置情報ベース）
- 降りたい駅の選択機能
- 選択駅のジオフェンス監視の開始・停止
- 駅圏内進入時のプッシュ通知（バイブレーション付き）
- 位置情報・通知パーミッションの要求
- 選択駅の永続化（アプリ再起動後の復元）

**対象外（作らないもの）:**

- 複数駅の同時監視（マルチゴール）
- ルートパターンの保存・適用
- 乗車履歴の記録
- 時刻表の表示
- オフライン対応（駅データのローカルキャッシュ）

### 2.2 各コンポーネントの役割

| コンポーネント | 技術 | 役割 |
|---|---|---|
| Flutterアプリ | Flutter (Dart) | ユーザーインターフェース。マップ表示・駅選択・監視開始・通知発火を担当 |
| OSジオフェンスサービス | iOS: CoreLocation / Android: Geofence API | 端末の位置情報を監視し、境界線の通過イベントを発火 |
| OS位置情報サービス | Geolocator | 現在地取得（近傍駅表示用）。10秒間隔でポーリング |
| 外部APIサーバー | toyohide.work | 全国の路線・駅データをJSON形式で提供 |
| 都道府県ポリゴンJSON | assets/json/japan_pref.json | 47都道府県の境界座標データ（ローカル） |
| 地図タイル | OpenStreetMap | flutter_mapで使用する地図タイル |

### 2.3 通信方式

| 項目 | 内容 |
|---|---|
| プロトコル | HTTP |
| データ形式 | JSON |
| 通信方向 | クライアント → サーバー（リクエスト/レスポンス型） |
| 通信方法 | HTTP POST |
| 認証 | なし |

### 2.4 ジオフェンスの仕組み

```
1. Flutterアプリがジオフェンスを登録（駅の座標 + 半径1000m）
            │
            ▼
2. OSがバックグラウンドで位置情報を監視
            │
            ▼
3. デバイスが駅の1000m圏内に入る
            │
            ▼
4. OSがコールバック関数を呼び出す
            │
            ▼
5. コールバック内で音量最大化 + プッシュ通知発火 + ループバイブレーション開始
```

## 4. 機能要件

### F-01 都道府県マップ表示

```
概要:    日本全国の都道府県ポリゴンを色分けして地図上に表示する
入力:    assets/json/japan_pref.json（ローカルGeoJSON）
処理:    GeoJSONをパースし、都道府県ごとにポリゴンを構築する。日本以外の地域は白マスクで覆う
出力:    48色でカラーリングされた都道府県ポリゴン地図（OpenStreetMapタイル上）
```

**表示ルール:**
- 都道府県は48色のカラーパレットで順番に色分けする
- 選択中の都道府県は白（不透明度85%）でハイライト、境界線は黒・太線で強調する
- 日本以外の地域は白ポリゴンで覆い、地図の焦点を日本に当てる

### F-02 都道府県選択

```
概要:    マップ上の都道府県ポリゴンをタップして選択状態にする
入力:    ポリゴンへのタップ操作（LayerHitNotifierによる検知）
処理:    タップされた都道府県名を取得し、選択状態として保持する
出力:    選択した都道府県のハイライト表示、都道府県名の表示、路線一覧ボタンの表示
```

### F-03 都道府県別駅データ取得

```
概要:    選択した都道府県の全路線・駅データをAPIから取得する
入力:    都道府県名（例: "東京都"）
処理:    3つのAPI（getTrain / getAllStation / getPrefTrainStation）を組み合わせて取得する
         取得後にF-18のデータ補正を適用する
出力:    補正済みの路線・駅リスト（路線名・駅名・座標・駅順を含む）
```

**異常系:**
- 通信エラー時はエラーメッセージを表示する

### F-04 路線・駅一覧表示

```
概要:    取得した駅データを路線ごとにグループ化して一覧表示する
入力:    F-03で取得した駅データ
処理:    路線名をヘッダー（ExpansionTile）とし、各駅を配下にリスト表示する
出力:    路線グループ化された駅リスト（駅名・座標）
```

**表示ルール:**
- 選択中の駅は黄色のCircleAvatar（不透明度60%）でインジケーター表示
- 非選択駅は黒のCircleAvatar（不透明度40%）
- 駅名の右下に緯度・経度をグレーで表示

### F-05 駅選択

```
概要:    路線・駅一覧から降りたい駅を1つ選択する
入力:    駅アイテムのタップ
処理:    選択状態をローカルステートで保持し、SharedPreferencesへ保存する
出力:    選択駅のインジケーター強調、ホーム画面の「目的地」表示更新
```

**動作ルール:**
- 選択できる駅は1つのみ（複数選択不可）
- 同じ駅を再タップすると選択が解除される
- 選択した駅名は画面上部「目的地：〇〇駅」に表示される

### F-06 ジオフェンス監視開始

```
概要:    選択した駅の座標にジオフェンスを登録し、監視を開始する
入力:    「設定」ボタンのタップ
処理:    選択駅の緯度経度を中心に、半径1000mのジオフェンスを登録する
出力:    ジオフェンス監視開始（AppBarの「watching」アイコンが黄色に変わる）
```

**動作ルール:**
- ジオフェンスのトリガーは「入場（圏内への進入）」のみ
- ジオフェンスID: `station_${駅名}`
- 監視開始時に既存ジオフェンスを全削除してから新規登録する

### F-07 降車通知

```
概要:    ジオフェンス圏内に入ったとき、音量最大化・ループバイブレーション・プッシュ通知で知らせる
入力:    OSからのジオフェンス入場イベント（バックグラウンド動作）
処理:    音楽ストリームの音量を最大にし、通知を発火し、バイブレーションをループさせる
出力:    音量最大化（Android のみ・音楽ストリーム）
        プッシュ通知（タイトル「降りる駅アラーム」、本文に駅名を表示）
        バイブレーション（ユーザーが停止操作するまで繰り返し）
```

**動作ルール:**
- アプリがバックグラウンドまたは終了状態でも動作する
- 音楽ストリームの音量を最大（1.0）に引き上げる（Android のみ）
- バイブレーションは最大強度（intensity 255）でパターンをループし続ける
- 通知タイトル: 「降りる駅アラーム」
- 通知本文: ジオフェンスIDを含む（駅名を含む）

### F-08 ジオフェンス監視停止

```
概要:    登録済みの全ジオフェンスを削除し、バイブレーションを停止する
入力:    AppBarの「stop（×）」ボタンのタップ
処理:    OSに登録済みのジオフェンスを全件削除し、ループ中のバイブレーションを停止する
         SharedPreferencesから選択駅情報を削除し、画面表示もリセットする
出力:    非監視状態への遷移（目的地表示が「(未設定)」に戻る）
```

### F-09 パーミッション要求

```
概要:    ジオフェンスと通知の動作に必要なパーミッションをユーザーに要求する
入力:    AppBarの「request（錠前）」ボタンのタップ
処理:    位置情報（Fine位置情報）→ 位置情報（常に許可）→ 通知の順に要求する
出力:    OSのパーミッションダイアログ表示、付与状況のアイコン更新
```

### F-10 目的地・距離表示

```
概要:    選択駅名と現在地からの距離をリアルタイムで表示する
表示内容:
  - 選択駅なし: 「目的地：(未設定)」（白文字）
  - 選択駅あり・GPS有効: 「目的地：〇〇駅（X.Xkm）」または「目的地：〇〇駅（XXXm）」（黄色文字）
  - 選択駅あり・GPS無効: 「目的地：〇〇駅」（黄色文字）
更新タイミング: GPSポーリング（10秒間隔）のたびに更新
```

### F-11 選択駅の永続化

```
概要:    アプリ再起動後も選択駅とジオフェンスを復元する
入力:    アプリ起動
処理:    起動時にSharedPreferencesから選択駅JSON文字列を読み込み、
         座標・駅名を復元してジオフェンスを再登録する
出力:    前回選択した駅名とジオフェンス監視が復元された状態
```

### F-12 近傍駅表示

```
概要:    現在地から指定半径内の駅を地図上にマーカーで表示する
入力:    GPSアイコンボタンのタップ（NearByStationsDisplayAlert の表示）
処理:    GPS位置情報を取得し、半径Xkm圏内の全駅を地図上にマーカー表示する
         現在地周辺の都道府県（30km圏内）のデータをバックグラウンドで自動取得する
出力:    駅名・距離が記載されたマーカー。現在地は青い点で表示
```

**表示ルール:**
- 未選択の駅マーカー: 青（不透明度85%）
- 選択中の駅マーカー: 赤（不透明度90%）
- 各マーカーに駅名と距離（X.XKm）を表示する

### F-13 近傍駅半径選択

```
概要:    近傍駅の表示半径をボタンで切り替える
選択肢:  1km / 3km / 5km / 10km / 20km
処理:    選択した半径に応じてフィルタリングし、地図のズーム範囲も合わせて変更する
```

### F-14 近傍駅からのジオフェンス設定

```
概要:    近傍駅マップで駅を選択し、「設定」ボタンでジオフェンスを登録する
処理:    駅マーカーをタップして選択（赤ハイライト）→「設定」ボタンでジオフェンス登録
         ダイアログを閉じた後、ホーム画面の目的地表示を更新する
```

### F-15 駅名検索

```
概要:    駅名を入力して路線内を検索し、BottomSheetから路線を選んでリストへジャンプする
入力:    「駅名検索」ボタンのタップ → BottomSheetでテキスト入力 → 検索ボタン
処理:    入力文字列で駅名を部分一致フィルタリングする
         結果をListTileで表示し、タップで該当路線の先頭へスクロールジャンプする
```

### F-16 路線ポリライン表示

```
概要:    路線の全駅座標をポリラインで地図に描画する
入力:    路線名横の「路線図（折れ線グラフ）」アイコンのタップ
処理:    選択した路線の全駅LatLngリストをPolylineLayerで描画する
         再タップで解除（都道府県全体表示に戻る）
```

### F-17 路線全域ズーム

```
概要:    選択路線の全駅が収まるよう地図をズームする
入力:    「路線全域（ページ）」アイコンのタップ（路線図表示中のみ表示）
処理:    路線全駅のLatLngからバウンディングボックスを計算し、fitCameraでズームする
         再タップで都道府県全体表示に戻す
```

### F-18 APIデータ補正

```
概要:    APIから取得した駅データの誤りを3段階のロジックで補正する
入力:    getPrefTrainStation APIのレスポンス
処理の流れ:
  ① stationMap補正   : getAllStation の駅順と異なる場合に駅順を補正する
  ② repairTrainNumber補正 : stationMapにない路線（複数路線番号をマージ）の補正
  ③ patchMap適用     : DataRepairクラスの手動パッチデータで駅リストを完全置換する
出力:    補正済みの PrefTrainModel リスト
```

### F-19 パーミッション状態表示

```
概要:    パーミッション付与済みかどうかをAppBarアイコンの色で示す
表示ルール:
  - 全パーミッション付与済み: 「request」アイコンが黄色
  - 未取得: 「request」アイコンが白
  - 選択駅あり: 「watching」アイコンが黄色
  - 未選択: 「watching」アイコンが白
```

## 6. データ設計

### 6.1 データの種類

| データ名 | 概要 | 主な項目 |
|---|---|---|
| 都道府県ポリゴンデータ | 47都道府県の境界座標 | 都道府県名、ポリゴン座標リスト（GeoJSON形式） |
| 路線情報 | 都道府県内の鉄道路線 | 路線番号、路線名、所属駅リスト |
| 駅情報 | 各駅の詳細情報 | 駅ID、駅名、住所、緯度、経度、駅順 |
| アプリ状態 | 選択都道府県、選択駅、現在地 | 選択都道府県名、選択駅情報、現在地座標（SharedPreferencesで永続化） |
| 近傍駅データ | GPS圏内の駅リスト | 全近傍都道府県の全駅モデルリスト（距離フィルタリング前） |

### 6.2 データの関係

```
┌──────────────────┐       ┌──────────────────┐
│  路線情報          │       │    駅情報          │
│                  │ 1   N │                  │
│  - 路線番号       │───────│  - 駅ID           │
│  - 路線名        │       │  - 駅名           │
│                  │       │  - 住所           │
│                  │       │  - 緯度           │
│                  │       │  - 経度           │
│                  │       │  - 駅順           │
└──────────────────┘       └──────────────────┘
                                    │
                                    │ ユーザーが1つ選択
                                    ▼
                           ┌──────────────────┐
                           │   選択駅          │
                           │（アプリ状態）      │
                           │  - 選択中の駅情報  │
                           │  - SharedPrefs永続化│
                           └──────────────────┘
```

### 6.3 データの取得タイミング

| データ | 取得タイミング | 保持方法 |
|---|---|---|
| 都道府県ポリゴンデータ | アプリ起動時にFutureで非同期読み込み | ローカルJSON（assets/json/japan_pref.json） |
| 路線・駅情報 | 都道府県タップ → 路線一覧ダイアログ表示時 | Riverpod Provider（keepAlive: true） |
| 近傍駅データ | 現在地の近傍都道府県が変化したとき自動更新 | Riverpod Provider（nearbyStations フィールド） |
| 選択駅情報 | 駅タップ時に保存、監視停止時に削除 | SharedPreferences（JSON文字列で永続化） |
| 現在地 | 10秒間隔のTimerポーリングで更新 | ローカル変数（`_currentPosition`） |

## 7. 外部インターフェース設計

### 7.1 API一覧

| API-ID | メソッド | エンドポイント | 概要 | 対応機能 |
|---|---|---|---|---|
| API-01 | POST | /BrainLog/api/getTrain | 全国路線番号→路線名の対応表を取得 | F-03 |
| API-02 | POST | /BrainLog/api/getAllStation | 全国の全駅データを取得（駅順補正の参照元） | F-03 |
| API-03 | POST | /BrainLog/api/getPrefTrainStation | 指定都道府県の路線・駅データを取得 | F-03 |

> **補足：** 都道府県別の路線・駅データ取得には3つのAPIを組み合わせる。API-01・API-02は駅順補正のための参照データとして使用し、API-03が実際に表示する路線・駅データを取得する。

### 7.2 通信シーケンス（都道府県別路線取得）

## 8. 非機能要件

### 8.1 性能要件

| 項目 | 要件 | 備考 |
|---|---|---|
| 都道府県マップ初期表示 | 3秒以内 | ローカルJSONの非同期読み込み |
| 都道府県別駅データ取得 | 5秒以内 | 3API呼び出しのため時間がかかる場合がある |
| 通知発火 | 圏内進入後できる限り短時間 | OSや省電力設定に依存 |
| GPS更新間隔 | 10秒ごと | Timerによる定期取得 |

### 8.2 可用性要件

| 項目 | 要件 |
|---|---|
| バックグラウンド動作 | アプリが終了状態でもジオフェンス監視・通知が機能すること |
| サーバー停止時 | エラーメッセージを表示。アプリはクラッシュしないこと |
| パーミッション未取得時 | 適切なガイダンスを表示し、アプリが停止しないこと |

### 8.3 ユーザビリティ要件

| 項目 | 要件 |
|---|---|
| 操作性 | 地図タップ → 路線・駅一覧 → 駅選択 → 設定 の直感的な操作フローで完了できること |
| テーマ | ダークテーマを採用する |
| バイブレーション | 到着時のバイブレーションはユーザーが停止操作するまでループし続けること |
| 距離表示 | 1000m以上は「X.Xkm」、未満は「XXXm」で表示する |

### 8.4 保守性要件

| 項目 | 要件 |
|---|---|
| API接続先 | `Environment` クラス（`data/http/client.dart`）で一元管理 |
| データモデル | Riverpod + freezedで状態管理。Widgetから直接API通信しない |
| データ補正ロジック | `DataRepair` クラスに集約し、UI・APIロジックと分離する |
| ファイル構成 | 役割別にディレクトリを分割（model / controllers / screens） |

### 8.5 セキュリティ要件

| 項目 | 現状 | 将来的な対応案 |
|---|---|---|
| 通信暗号化 | HTTP（非暗号化） | HTTPS化を推奨 |
| 位置情報の扱い | 通知発火・近傍駅検索にのみ使用。外部には送信しない | 変更なし |
| 認証 | なし | 必要に応じてAPI Key等を導入 |

## 9. 用語集

| 用語 | 意味 |
|---|---|
| ジオフェンス | 地図上に設定した仮想的な境界線。境界線の通過時にイベントが発火する |
| 都道府県ポリゴン | GeoJSONで定義された都道府県境界の多角形。flutter_mapで描画する |
| 近傍駅 | 現在地から指定半径以内にある駅 |
| バックグラウンド動作 | アプリが表示されていない・終了している状態でも機能する動作 |
| DataRepair | APIの駅データ誤りを補正するクラス。3段階の補正ロジックを持つ |
| stationMap補正 | getAllStation APIの駅順を参照してgetPrefTrainStation APIの駅順を補正する処理 |
| patchMap | 手動で定義した正確な駅データ。誤座標・欠落駅・誤順序を修正するために使用 |
| keepAlive | Riverpod Providerの設定。アプリのライフサイクル全体でデータを保持し続ける |
| LayerHitNotifier | flutter_mapのポリゴンタップを検知するための仕組み |
